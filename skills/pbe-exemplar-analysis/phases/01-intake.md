# Phase 1: Intake — Exemplar Analysis

## Purpose

Select exemplar code paths and load S4 context.

## Intake steps

### Step 1: Load S4 pointers

- Candidate ID
- Exemplar path list from S4 output
- Rule of Three context descriptions

### Step 2: Select primary exemplar

Choose clearest, tested implementation for deep read.

Secondary exemplars for variability comparison.

### Step 3: Access code

Read paths; note language, test files, package structure.

### Step 4: S2 quick check

If exemplar violates dependency rule badly, note as caution—not disqualifier if fixable in spec guidance.

### Step 5: Intake checklist

- [ ] ≥1 exemplar path confirmed
- [ ] S4 candidate ID linked
- [ ] Tests located for primary exemplar

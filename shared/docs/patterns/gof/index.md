# GoF / HFDP design patterns

Load **≤3** concepts by id (`gof/<slug>`) after `./scripts/adlc5 patterns lookup --group gof`. Do not paste this whole list into chat. Deep essay (on demand): `../knowledge-base/04-design-patterns.md`.

* [Strategy](strategy.md) - Interchangeable algorithms or behaviors behind a common interface.
* [Observer](observer.md) - One-to-many notification when subject state changes.
* [Decorator](decorator.md) - Add responsibilities to an object at runtime without subclass explosion.
* [Factory Method](factory-method.md) - Subclass (or override) decides which concrete product to create.
* [Abstract Factory](abstract-factory.md) - Create families of related products without specifying concrete classes.
* [Singleton](singleton.md) - Ensure a class has exactly one instance with a global access point.
* [Command](command.md) - Encapsulate a request as an object for queues, undo, or macros.
* [Adapter](adapter.md) - Translate an incompatible interface into one clients expect.
* [Facade](facade.md) - Provide a simple interface to a complex subsystem.
* [Template Method](template-method.md) - Define algorithm skeleton in a base class; subclasses vary steps.
* [Iterator](iterator.md) - Sequential access to aggregate elements without exposing structure.
* [Composite](composite.md) - Treat individual objects and compositions uniformly in a tree.
* [State](state.md) - Alter behavior when an object's internal state changes.
* [Proxy](proxy.md) - Control access to an object (lazy load, remote, protection).
